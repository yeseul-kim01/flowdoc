# 기능 개발 문서 (features/)

기능을 개발하기 **전에** 여기 문서를 읽고, 개발하는 기능마다 여기 문서를 **하나 추가**한다.
한 기능 = 한 파일. 번호 순서대로 쌓는다 (`0001-...`, `0002-...`).

이 폴더의 목적은 두 가지다.
1. **착수 전 컨텍스트 로딩** — 새 기능을 잡기 전에 아래 "항상 먼저 읽기"를 훑어 패리티/스펙 계약을 깨지 않게 한다.
2. **기능 단위 설계 기록** — 무엇을·왜·어떻게(단계 분할 포함)를 한 파일에 남겨, 작업 중간에 끊겨도 이어서 할 수 있게 한다.

## 기능 문서 쓰는 법

새 기능은 [_template.md](_template.md)를 복사해 `NNNN-<짧은-슬러그>.md`로 만든다.
한 문서는 다음을 답한다:

- **무엇 / 왜** — 무슨 기능이고 어떤 가치인가 (ideas.md 항목/등급 연결).
- **스펙 영향** — `flowdoc.json`에 만드는 노드/엣지/필드. 스키마 변경이 끼면 **공유 계약** → 양측 합의 필요.
- **아키텍처 + 기술 난제** — 어떻게 구현하나, 어디가 어려운가.
- **단계 분할** — Phase 1(시연 가능한 MVP) → 2 → 3.
- **패리티** — Spring/FastAPI 양쪽에서 같은 스펙이 나오나? 한쪽 구현 후 패리티 이슈로 미러 (collaboration.md).
- **완료 기준** — 같은 `ui/index.html`에서 동일하게 보이고 스키마 통과.
