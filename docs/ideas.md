# FlowDoc 시각화 아이디어 (백로그)

호출 흐름(구조 뷰) **외에** 백엔드 협업에서 보면 좋을 뷰들의 아이디어 모음.

핵심 통찰: **대부분은 같은 `flowdoc.json`의 다른 렌즈다.** 지금 스펙에 이미 노드·엣지·
어노테이션·패키지·트랜잭션 마커·가드·외부 경계가 들어있으므로, 그래프를 다르게 읽기만 하면
스캐너를 안 고치거나 거의 안 고치고도 그릴 수 있다.

**실현성 등급**
- ✅ **스펙 그대로** — 지금 `flowdoc.json`만으로 UI 뷰 추가하면 됨 (스캐너 0수정)
- 🔧 **소수정** — 스캐너에 작은 추출 추가 (대개 어노테이션 한두 개 더 매핑)
- 🔬 **추가 파싱** — 필드/본문 등 더 깊은 정적 분석 필요
- ⏱ **런타임** — v0.3 트레이스 오버레이가 있어야 함

> speaknote(207파일) 스캔 결과를 예시로 인용한다. 실데이터로 개념이 검증된 항목들이다.

## A. 그래프 렌즈 — 구조에서 바로 나오는 것

### A1. 공통 유틸 / 허브 뷰 ✅
함수를 **fan-in(서로 다른 호출자 수)** 으로 랭킹하고 `global.*`/`util` 패키지를 그룹핑.
- **가치**: 중복 구현 방지, 온보딩("뭐부터 보면 되나"), **"이거 건드리면 N곳 터짐" 핫스팟** 경고.
- **speaknote 실측**: `BaseResponse.success`(13개 클래스가 호출), `UserFinder.getActiveUser`(9),
  `BaseEntity.deactivate`(5), `JwtTokenProvider`/`RedisService`/`PdfValidator`가 상위. `global.*`
  사용량: BaseResponse 24, WebSocketSessionManager 19, JwtTokenProvider 12 …

### A2. 역방향 호출 / 영향도 뷰 ✅
엣지를 뒤집어 "이 함수를 **누가** 부르나" 트리. 정방향 흐름의 거울.
- **가치**: PR 리뷰·리팩터링에서 가장 자주 묻는 "이거 바꾸면 어디 영향?"에 직답.

### A3. 계층 위반 감지 ✅
패키지/스테레오타입(`@RestController`·`@Service`·`@Repository`) 기준으로 잘못된 방향의 간선 표시.
- **가치**: controller가 repository 직접 호출, service가 controller 호출 같은 레이어링 깨짐을 PR 전에 발견.

### A4. 도메인 / 모듈 결합도 맵 ✅
패키지(`domain.note`, `domain.user`, `infrastructure.python`…)를 노드로 묶은 의존 그래프 + **순환 의존** 표시.
- **가치**: 모놀리식 안에서 모듈 경계가 새는 곳, 분리 후보 식별.

### A5. 엔드포인트 카탈로그 ✅
`@FlowEntry` 유무와 무관하게 **모든 `@*Mapping`** 을 메서드+경로+계층으로 나열 (Swagger식 인덱스).
- **가치**: API 전수 목록. speaknote 기준 ~75개 엔드포인트.

### A6. 고아 / 데드 노드 ✅
어떤 진입점에서도 도달 불가한 함수 = 죽은 코드 후보.
- **가치**: 631노드 중 미도달분 정리.

### A7. fan-out 핫스팟 (God method/class) ✅
한 함수가 **너무 많은** 다른 것을 호출 → 책임 과다(거대 서비스) 후보.
- **가치**: 분해 대상 식별. A1(fan-in)의 반대편.

### A8. 복잡도 / 깊이 맵 ✅
흐름별 최대 깊이, 노드 수, 사이클(`↻`) 표시.
- **가치**: 가장 복잡한 흐름 = 리뷰·테스트 우선순위.

## B. 위험 / 품질 감사 — 어노테이션 × 마커

### B1. 트랜잭션 위험 감사 ✅ (FlowDoc만의 차별점)
`@Transactional` 경계 **안에서** 일어나는 외부 I/O(repository·파일·HTTP·`@Async`) 하이라이트.
- **가치**: 긴 트랜잭션·커넥션 점유·외부호출 in-tx 발견.
- **speaknote 실측**: `createNote`가 tx 안에서 `StorageService.store`(파일 업로드)와 async Python 분석
  호출까지 한다 → 트랜잭션이 파일 I/O 동안 열려 있는 리스크.

### B2. async-after-commit 정합성 ✅
`@Async` 자식이 tx 레일 밖에 있음을 명시 + "여기 실패해도 본 트랜잭션 롤백 안 됨" 경고.
- **가치**: 커밋 후 후처리의 의도/실패 격리 가시화.

### B3. 보안 게이트 커버리지 🔧 (어노테이션은 이미 캡처됨)
`@PreAuthorize`/`@Secured`/`@AuthenticationPrincipal` 유무로 엔드포인트 색칠 → **인증 안 걸린 엔드포인트 빨강**.
- **가치**: 보안 리뷰 한눈에. (역할 매핑만 추가하면 됨)

### B4. 동시성 가드 맵 🔧
`@Guarded`/JPA `@Lock`/`@DistributedLock`을 **자원(resource)별**로 묶어 어디서 무엇을 잠그는지 + 잠금 중첩(데드락 후보).
- **가치**: 동시성 핫스팟·락 순서 문제 사전 발견.

### B5. 트랜잭션 전파 충돌 🔧
`propagation`(REQUIRES_NEW 중첩 등)을 흐름 위에 표시.
- **가치**: 의도치 않은 신규 트랜잭션/합류 발견. (정적 한계는 런타임이 보강 — §9)

### B6. 검증 누락 🔧
`@RequestBody`인데 `@Valid`/`@Validated` 없는 진입점 표시.
- **가치**: 입력 검증 빠진 곳 점검.

### B7. 캐시 경계 / 재시도·폴백 🔧
`@Cacheable`↔`@CacheEvict` 짝, `@Retryable`/`@CircuitBreaker`의 폴백 간선(대체 경로).
- **가치**: 단락 가능 지점과 복원력 경로 가시화 (§6.2).

## C. 데이터 / 영속성

### C1. 엔티티 ↔ 흐름 매트릭스 🔧
"어떤 흐름이 어떤 테이블/엔티티(repository)를 건드리나"를 매트릭스로. (외부 경계 노드 이미 있음 → repository→엔티티 매핑만 추가)
- **가치**: 스키마 변경 영향 범위, 도메인별 데이터 접근 파악.

### C2. 쓰기 경로 추적 🔧
`@Modifying`/`save`/`delete`가 트랜잭션 밖에서 일어나는 곳 표시.
- **가치**: 원자성 깨지는 쓰기 발견.

### C3. ERD (엔티티 관계도) 🔬
`@Entity`/`@ManyToOne`/`@OneToMany` 필드 파싱 → 엔티티 관계 그래프.
- **가치**: DB 모델 문서 자동화. (필드 레벨 분석 필요)

### C4. N+1 후보 🔬
루프 안에서 repository 호출 탐지.
- **가치**: 성능 안티패턴 사전 경고. (본문 흐름 분석 필요)

## D. 외부 연동 / 진입점

### D1. 외부 의존 맵 ✅
"어떤 흐름이 S3·Redis·Mongo·Python·메일·결제 PG를 건드리나"를 외부 경계 노드/`infrastructure.*`로 집계.
- **가치**: 외부 장애 시 영향 흐름, 벤더 결합도. speaknote는 STT(Google)·결제(Toss)·S3·Redis·Mongo 혼재.

### D2. 진입점 종류별 트리거 카탈로그 🔧
HTTP뿐 아니라 `@KafkaListener`·`@Scheduled`·`@EventListener`·WebSocket을 트리거 종류로 분류 (§6.2).
- **가치**: "흐름은 컨트롤러에서만 시작하지 않는다" — 배치·이벤트·소켓 진입점도 한 곳에.

### D3. 이벤트 발행 ↔ 핸들러 맵 🔬
`@FlowLink`/이벤트 타입 매칭으로 발행→핸들러 점선 연결 (`callType: event`).
- **가치**: 디커플링된 비동기 연결 가시화 (로드맵 v0.4).

## E. 협업 / 프로세스

### E1. 변경 영향 미리보기 (PR 뷰) ✅+
`git diff`로 바뀐 메서드 → A2(역방향 호출)로 "이 PR이 건드리는 흐름" 자동 표시.
- **가치**: 리뷰어가 영향 범위를 즉시 파악. (CI에 붙이면 PR 코멘트화)

### E2. 흐름 diff (스펙 버전 비교) ✅
두 `flowdoc.json`을 비교해 **새로 생긴/사라진 간선·노드** 강조.
- **가치**: "이번 변경으로 흐름이 어떻게 달라졌나"를 시각적 diff로.

### E3. 코드 소유권 / 도메인 책임 맵 ✅
패키지→도메인별로 노드를 색칠, 도메인 간 호출을 경계로.
- **가치**: 누가 어느 영역을 책임지나, 코드오너 매핑.

## F. 런타임 오버레이 (v0.3, ⏱ 트레이스 필요)

같은 그래프 위에 **실제 실행**을 덧칠.
- **F1. 핫패스** — 자주 타는 간선 강조, 안 타는 분기는 흐리게
- **F2. 레이턴시 히트맵** — 노드/구간별 실제 소요 시간
- **F3. 실제 트랜잭션 생명주기** — begin→commit→rollback, 신규 vs 합류
- **F4. 세마포어 점유 구간** — 임계 구역 실제 지속 시간 (`acquiredAt`/`releasedAt`)
- **F5. 실패율 / 예외** — 어느 간선에서 얼마나 터지나

## G. 다른 직군과의 협업 (FE · QA · 운영)

백엔드 *내부* 구조를 넘어, 같이 일하는 사람에게 보여줄 때 가치가 큰 것들.

### G1. API 계약 변경 감지 (breaking change) 🔬
두 버전 사이 요청/응답 DTO **필드 추가·삭제·타입 변경**을 진단 → "이 PR이 프론트 깨뜨림" 경고.
- **가치**: FE-BE 협업의 1순위 사고 예방. (DTO 필드 파싱 + 버전 비교 필요)

### G2. 에러 / 응답 카탈로그 🔧
엔드포인트별로 던질 수 있는 예외 → HTTP status 매핑 (`@RestControllerAdvice`/`throws`/`@ResponseStatus`).
- **가치**: FE가 매번 묻는 "이 API 어떤 에러 줄 수 있어?"에 자동 응답. speaknote엔 `GlobalExceptionHandler` 존재 → 매핑 추출 가능.

### G3. 외부 API 호출 인벤토리 🔬
우리가 **호출하는** 외부 시스템/URL 목록 (Toss·Google STT·S3·메일 등).
- **가치**: 벤더 의존 관리, 외부 장애 대응 범위. (본문에서 클라이언트 호출 추출 필요)

### G4. 설정 / 환경변수 의존 맵 🔧
`@Value`/`@ConfigurationProperties` → 어떤 코드가 어떤 설정키를 쓰나.
- **가치**: "이 env/시크릿 바꾸면 어디 영향?" — 배포·인프라 담당과의 협업. (지금은 무시 어노테이션이지만 역으로 수집)

### G5. 테스트 커버리지 오버레이 🔬
`src/test`도 스캔해 **테스트 → 운영 메서드 호출**을 매핑 → 흐름 위에 "테스트 있음/없음" 색칠.
- **가치**: 리뷰·QA 때 "이 흐름 테스트 됨?" 즉답. 미검증 경로 빨강.

## H. 기술부채 · 안전

### H1. `@Deprecated` 오버레이 ✅
deprecated 메서드가 **아직 어떤 흐름에서 쓰이나** 표시 (어노테이션 이미 캡처됨).
- **가치**: 제거 가능 여부·잔존 사용처 파악.

### H2. 순환 의존 / 호출 사이클 리스트 ✅
A8의 `↻`를 전용 목록으로 — 사이클에 낀 메서드/패키지 모음.
- **가치**: 리팩터링 타깃 1순위.

### H3. 민감 작업 흐름 태깅 🔧
삭제·결제·관리자·인증변경 등 위험 엔드포인트를 별도 색/필터 (경로 패턴 + 어노테이션).
- **가치**: 보안·감사 리뷰 집중 대상. speaknote: `payments/confirm`, `notes/{id}` DELETE 등.

### H4. 동기 / 비동기 경계 전체 맵 ✅
스레드가 갈라지는 지점(`@Async`/WebFlux `Mono`·`Flux`)을 코드베이스 전체로 표시.
- **가치**: speaknote처럼 web+webflux+async 혼재일 때 "어디서 비동기로 새나" 파악.

## I. 산출물 & 자동화

### I1. 마크다운 / 문서 export ✅
`flowdoc.json` → PR·위키용 흐름 문서(마크다운/머메이드) 자동 생성.
- **가치**: 협업 산출물을 코드에서 자동 — "흐름 문서 손으로 안 그림".

### I2. PR 봇 / CI 통합 ✅+
E1(변경 영향) 결과를 PR 코멘트로 자동 게시.
- **가치**: 리뷰어가 PR 안에서 영향 범위·새 흐름을 바로 봄.

### I3. 온보딩 큐레이션 ✅
도메인별 "핵심 흐름 N개"를 fan-in/진입점 기준으로 자동 추천.
- **가치**: 신규 입사자가 "뭐부터 읽나"를 자동으로.

### I4. 메시징 토폴로지 🔬
Kafka/Rabbit `producer → topic → consumer` 맵 (D3 이벤트 맵의 메시징 버전).
- **가치**: 비동기 메시징 흐름 가시화.

## 추천 우선순위

협업 임팩트 ÷ 구현 비용 기준:

1. **A1 공통 유틸 허브** + **A2 역방향 영향도** — 둘 다 ✅, PR/리팩터링에서 매일 쓰는 질문.
2. **B1 트랜잭션 위험 감사** — ✅에 가깝고 Swagger·일반 콜그래프엔 없는 **FlowDoc만의 차별점**.
3. **A5 엔드포인트 카탈로그** + **B3 보안 커버리지** — API 전수 + 인증 공백, 거의 공짜.
4. **A3/A4 계층·결합도** — 아키텍처 리뷰용.
5. **직군 협업 저비용**: **I1 문서 export** · **G2 에러 카탈로그** · **G4 설정 의존 맵** · **I3 온보딩 큐레이션** — FE/운영/신규 입사자에게 바로 가치.

이후 C·D·E·G·H로 확장, F·G1·G5·I4는 추가 파싱/런타임(v0.3+) 이후.

> 메타 원칙은 동일: **파서가 읽을 수 있는 건 사람에게 시키지 않는다.** 위 대부분은 이미 코드에
> 박힌 어노테이션·구조에서 나오므로 추가 선언이 거의 없다 ([flowdoc-기획안.md](flowdoc-기획안.md) §5).
